# バグ調査

コードをすぐに変更しない。

以下の順番で調査する。

1. 問題を再現する。
2. 期待される挙動を整理する。
3. 実際の挙動を整理する。
4. 最小の再現条件を特定する。
5. 関連するコードを探す。
6. 必要に応じてSerenaでsymbolやreferenceを調査する。
7. 原因仮説を立てる。
8. 仮説を証拠で検証する。
9. Root Cause（根本原因）を特定する。
10. 必要最小限の修正を行う。
11. 可能であればRegression Test（再発防止テスト）を追加する。
12. 関連テストを実行する。
13. 元の再現手順でもう一度確認する。
14. ブラウザ上の問題であればPlaywrightで確認する。

ライブラリやフレームワークの仕様が原因候補の場合、推測せずContext7で現在の公式仕様を確認する。

最後に以下を整理する。

- 症状
- 根本原因
- 修正内容
- 検証内容
- 残っているリスク
